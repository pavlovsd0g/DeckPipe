## UI structure

- 172 descendants in the rendered accessibility document.
- 10 keyboard-focusable controls in the initial state.
- Playlist cards are rendered as non-focusable groups, so none of the 39
  Deezer playlists can be selected with the keyboard.
- At the configured minimum inner size (1,000 × 640), the Save control is
  clipped and the Bug-report control is outside the visible viewport.

## Scaling risks found statically

- Playlist scan performs fuzzy matching against the full disk file list for
  every track (`O(tracks × files)`).
- Every track status update reloads and rewrites the full JSON sidecar.
- The frontend rebuilds large playlist and track collections using
  `innerHTML`; there is no virtualization.
- Download jobs are in-memory and serial; WAV flips create independent
  thread pools with an unbounded caller-supplied worker count.

Cold-start timing was not retained as a success metric: closing the GUI left
both backend processes alive for more than 12 seconds. That lifecycle failure
is more important than a launch-time number and is documented in the audit.
