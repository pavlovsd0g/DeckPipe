> Plan mode. Рабочее название: **DeckPipe** (можно переименовать).
> Дата: 2026-07-28. Окружение: Windows, Rekordbox **7.2.14** (`C:\Program Files\rekordbox\rekordbox 7.2.14`),
> база `C:\Users\Никита\AppData\Roaming\Pioneer\rekordbox6\master.db`.

## 1. Что выяснено по кирпичикам

### Saturn
- Saturn ([github.com/Sheathed/Saturn](https://github.com/Sheathed/Saturn)) — кроссплатформенный **Flutter/Dart**-клиент Deezer (GPL-3.0), требует премиум-аккаунт, качает FLAC. Текущая версия v3.0.13 (июнь 2026).
- Форкать Saturn целиком **нецелесообразно**: это UI-плеер на Dart, нашего сценария (синк плейлистов ↔ файлы ↔ Rekordbox) там нет, а тащить Flutter-приложение ради движка загрузки — лишний вес.
- **Вывод:** делаем своё приложение, а «движок Saturn» воспроизводим через готовую Python-библиотеку того же класса — **deezspot** ([Xoconoch/deezspot-fork-again](https://github.com/Xoconoch/deezspot-fork-again)): логин по ARL-токену, `download_playlistdee()` / `download_trackdee()`, качество FLAC, кастомные шаблоны имён файлов/папок. Альтернативы-фолбэки: `deezload`, `godeez` (CLI на Go).

### Deezer API (чтение плейлистов)
- Публичные плейлисты читаются без авторизации: `api.deezer.com/playlist/{id}` + `/tracks`.
- Свои плейлисты: `api.deezer.com/user/me/playlists` (OAuth) **или** через внутренний GW API с тем же ARL, что и в Saturn.
- Скачивание FLAC официальным API невозможно (только 30-сек превью) — поэтому скачивание только через ARL-подход (deezspot).

### Rekordbox (хранилище данных)
- `master.db` — SQLite, зашифрован **SQLCipher4**, ключ извлекается локально. **pyrekordbox** ([dylanljones/pyrekordbox](https://github.com/dylanljones/pyrekordbox)) открывает, читает и пишет (tested до 7.0.9; у нас 7.2.14 — нужен спайк).
- Структура (подтверждено документацией формата):
  - `djmdContent` — треки: `FolderPath`, `FileNameL`, `FileType` (flac=5, wav=11), `BPM`, `Rating`, `ColorID`, `AnalysisDataPath` (путь к ANLZ-файлам с сеткой/волнами) и т.д.
  - `djmdCue` — hot/memory cue, лупы: `InMsec`, `Kind` (0=memory, N=hot), `Color`, `Comment`.
  - `djmdPlaylist` + `djmdSongPlaylist.TrackNo` — плейлисты и **порядок треков**.
  - `djmdSongMyTag` — MyTags.
- pyrekordbox умеет: читать всё; менять «простые» поля контента (`db.commit()`); добавлять/удалять треки, плейлисты, записи в плейлистах.
- XML-мост (`rekordbox.xml`) поддерживает `POSITION_MARK` (кью) и `TEMPO` (сетка/BPM) — импорт кью и сетки в Rekordbox работает (это рабочий механизм DJCU/Mixed In Key).

### FLAC→WAV и метки
- Кью/сетка/BPM в Rekordbox привязаны к **ContentID**, а не к файлу. Сдвиг на ~26 мс при смене файла — проблема только **lossy**-кодеков (mp3/m4a, задержка кодера). FLAC→WAV — lossless, смещения не будет.
- Значит правильная стратегия — **не создавать новый трек**, а «подменить файл» у существующего: конвертнуть FLAC→WAV и обновить в `djmdContent` поля `FolderPath`, `FileNameL`, `FileType=11`, `SampleRate`, `BitDepth`, `FileSize`. ContentID не меняется → сохраняются ВСЕ кью, лупы, сетка (ANLZ), рейтинги, цвета, MyTags, позиции в плейлистах.
- ⚠️ Сначала проверить: **CDJ-2000NXS2 / CDJ-3000 / XDJ-XZ и новее играют FLAC нативно**. Если на студии такие — вся конвертация не нужна: Rekordbox сам экспортирует FLAC + анализ на USB.

### Пути: глобальный корень + переопределение на плейлист

- **Корень библиотеки (`MUSIC_ROOT`)** — указывается в настройках (например `D:\Music` или `C:\Users\Никита\Music\DeckPipe`). По умолчанию каждый плейлист живёт в `MUSIC_ROOT\<PlaylistName>\`.
- **Кастомный путь плейлиста** — у каждого плейлиста можно переопределить папку: она может лежать где угодно, **в том числе на флешке/USB-диске** (например `E:\Playlists\StudioSet\`). Пригодно и для сценария «плейлист уже существует отдельно» — просто указываем существующую папку, sidecar досоздаётся внутри неё.
- Хранение привязки: в конфиге приложения `playlists.json`: `{deezer_playlist_id, name, path (abs), is_custom}`. Источник истины о треках — sidecar `.deckpipe.json` **внутри папки плейлиста**, поэтому папку можно переносить/втыкать с флешки — достаточно пересканировать.
- WAV-flip учитывает кастомный путь: WAV-версия пишется рядом (`<path>_WAV\`) или в указанную отдельную папку (например сразу на флешку, с которой играешь на CDJ).

### Нестабильная буква USB-диска (подтверждено: буква плавает)

`master.db` хранит абсолютные пути с буквой диска, а Windows может выдать флешке другую букву. Решение — три уровня:

1. **Идентификация тома, а не буквы.** В конфиге путь на съёмном носителе хранится как `{volume_serial | volume_label}:\относительный\путь`. При каждом запуске/операции приложение перебирает диски (`GetVolumeInformation` / WMI) и резолвит актуальную букву по **серийному номеру тома** — он уникален и не меняется при переподключении. В UI диск показывается по метке (например «CDJ-USB»), а не по букве.
2. **Шаг «Fix letters» перед записью в master.db.** Перед любым flip/синком сверяем пути в `djmdContent` для USB-файлов с текущей буквой тома. Если буква съехала — сначала пакетно обновляем букву в путях (тот же механизм UPDATE при закрытом Rekordbox + бэкап), потом выполняем основную операцию. Так Rekordbox не увидит «missing files» из-за смены буквы.
3. **Рекомендация (опционально, вне приложения):** закрепить букву за флешкой средствами Windows («Управление дисками» → «Изменить букву диска») или утилитой USBDLM (назначает букву по ID устройства). Не обязательно — приложение работает и без этого, — но сокращает число fix-проходов.

Формат трека фиксируем в sidecar (`format: flac|mp3`): часть треков на Deezer есть только в MP3 — их забираем в MP3_320 (deezspot умеет автоматический fallback `recursive_quality`), в UI показываем бейдж формата.

Почему локальный веб-UI, а не Electron/Tauri на старте: быстрее итерировать, браузер уже есть. Позже можно обернуть в Tauri для «одного exe».

## 3. Сценарии

### A. Синк Deezer → файлы
1. Ввод ARL (один раз, храним локально; ARL периодически истекает — UI покажет статус авторизации).
2. Загрузка плейлистов юзера → треклисты.
3. Статус по sidecar-JSON + скану папки: есть / нет / частично.
4. Чекбоксы по трекам или «Синхронизировать всё» → очередь deezspot → FLAC (или MP3_320, если FLAC недоступен) в папку плейлиста.

### A2. Поиск (треки / альбомы / исполнители) — как в Saturn
1. Строка поиска с табами «Треки / Альбомы / Исполнители». Источник: публичный `api.deezer.com/search` (работает без авторизации; с ARL — GW-поиск, результаты богаче).
2. У каждого результата — действия:
   - **Скачать в…** → выбор локального плейлиста → трек качается в его папку. Если локальный плейлист привязан к плейлисту Deezer — трек **автоматически добавляется и в плейлист Deezer** (одна сущность «плейлист» = пара «deezer-плейлист ↔ локальная папка»).
   - **В плейлист Deezer (без скачивания)** → только добавление в плейлист на сервисе; локально появится как «✖ нет» до следующего синка.
   - **Создать плейлист** → новый плейлист в Deezer + локальная папка с sidecar.
3. Альбом целиком: «Скачать в…» → все треки альбома; «В плейлист» → добавить все треки альбома.
4. Запись в Deezer (создание плейлиста, добавление треков) — через GW API с тем же ARL (методы `playlist.create` / `playlist.addSongs`; так же делает Saturn). Фолбэк: официальный OAuth (scope `manage_library`) — требует регистрации приложения в Deezer, поэтому запасной вариант. **Спайк №2** проверяет, что GW-запись реально работает с твоего аккаунта.

### B. Синк файлы → Rekordbox
- **MVP (безопасный):** генерируем `rekordbox.xml` (плейлисты + треки по путям файлов) → импорт в Rekordbox через File → Import → rekordbox xml. Автоанализ BPM/сетки делает сам Rekordbox при импорте.
- **Полный автомат (опция «эксперт»):** прямая запись в `master.db` через pyrekordbox (`add_content`, `add_playlist`, `add_song_to_playlist`). Условия: Rekordbox закрыт, перед записью — бэкап `master.db` (у юзера уже лежат `master.backup*.db`, добавим свой ротационный бэкап). Минус: треки без анализа → нужно отдельно прогнать анализ в Rekordbox.

### C. «Уезжаю на студию» (FLAC⇄WAV flip)
> Правило: на студии разные CDJ → **WAV-библиотека как базовый стандарт**. Дома играем FLAC/MP3, перед выездом — flip в WAV.
1. Выбор плейлиста → кнопка «Подготовить для CDJ».
2. Для каждого трека: ffmpeg FLAC/MP3→WAV (44.1/48 кГц, 16/24 бит — настраиваемо) в `PlaylistName_WAV\`.
   **Параллельная конвертация по ядрам** (схема как в dBpoweramp DSP): пул воркеров = числу физических/логических ядер CPU (выбор в настройках), каждый воркер — отдельный процесс ffmpeg; очередь треков раздаётся по воркерам, прогресс по файлам в UI. Декодирование FLAC/MP3→PCM в ffmpeg однопоточное на файл, поэтому выигрыш именно от N параллельных процессов — на 8-16 потоках плейлист конвертится в разы быстрее.
3. При закрытом Rekordbox: UPDATE `djmdContent` (путь → .wav, FileType=11, SampleRate/BitDepth/FileSize) → бэкап → commit.
4. Все кью/сетка/звёзды/цвета/порядок на месте, т.к. ContentID прежний. ⚠️ Для треков, изначально бывших **MP3**, кью могут «поехать» на доли мс (задержка lossy-кодера при декодировании) — это известный эффект (~26 мс). Митигация: компенсируем сдвиг при записи кью ИЛИ помечаем такие треки в UI («mp3-источник, проверь сетку»). FLAC-источники сдвига не имеют.
5. «Вернулся домой» — обратный flip на FLAC/MP3 (тот же UPDATE на исходный файл).
6. Фолбэк-режим без записи в БД: экспорт XML с POSITION_MARK/TEMPO на новые пути → ручной импорт (треки продублируются — хуже, но безопасно).

### D. Проверка целостности + лист ошибок
> Мотивация: треки периодически «ломаются» на загрузке или конвертации (обрезаны в конце, файл не читается). Битый трек не должен молча попадать в библиотеку и на CDJ.

**Проверка после загрузки** (каждый трек, сразу в пайплайне):
1. Файл существует, размер > 0, mutagen/ffprobe читают заголовок и теги — иначе `corrupt`.
2. Полное декодирование без ошибок: `ffmpeg -v error -i <file> -f null -` — любая ошибка декодера = брак.
3. Сравнение длительности: фактическая (`ffprobe`) vs ожидаемая из метаданных Deezer (`duration` трека). Допуск ±2 c (у Deezer бывают расхождения в секунду). Меньше — значит «обрезан в конце».

**Проверка после конвертации** (FLAC/MP3→WAV):
1. Полное декодирование WAV без ошибок.
2. Длительность WAV vs длительность исходника, допуск ±0.5 c.

**Лист ошибок:**
- Трек, не прошедший проверку, помечается в sidecar (`status: verify_failed_download | verify_failed_convert`, причина в `error`) и появляется на вкладке «Ошибки»: трек, плейлист, этап, причина (обрезан / не декодируется / не читается).
- **Авто-ретрай**: 2 автоматические попытки того же этапа сразу (перекачать/переконвертировать). Не помогло — в лист ошибок.
- **Ручной перезапуск**: кнопка «Повторить» у трека (перезапускает именно сломавшийся этап) и «Повторить все». Успешный перезапуск снимает трек из листа и обновляет статус.
- Битый файл не удаляем до успешной замены (вдруг частично пригоден) — лежит с пометкой; после успешного ретрая старый замещается.
- В списке плейлиста такие треки показываются отдельным статусом «⚠ ошибка», а не «✔ есть», чтобы не уехать на студию с обрезанным WAV.

## 5. Риски и открытые вопросы

1. **Запись в master.db недокументирована** — Pioneer может поменять схему в апдейтах. Митигация: бэкап перед каждой записью, писать только при закрытом RB, фиче-флаг.
2. pyrekordbox tested до 7.0.9, у нас 7.2.14 → спайк №0 обязателен.
3. Автоанализ при прямой записи в БД не запускается → для новых треков сетку всё равно делает Rekordbox (вручную или при XML-импорте). Для flip-режима это не проблема (ANLZ уже есть).
4. **Запись в Deezer (плейлисты) через GW API** — неофициальный эндпоинт, может отличаться/ломаться. Спайк №2 проверяет до постройки UI. Фолбэк: официальный OAuth с `manage_library`.
5. **MP3-источники**: часть треков на Deezer только в MP3 → качаем MP3_320; при конвертации MP3→WAV возможен сдвиг кью ~26 мс (задержка кодера) — компенсация или пометка в UI. FLAC-источники сдвига не имеют.
6. ARL живёт ограниченное время — UI должен просить обновить.
7. Deezer периодически ломает ARL-загрузчики (как убили deemix) — deezspot может внезапно умереть; держим фолбэк на godeez.
8. На студии разные CDJ → **WAV как базовый формат библиотеки для выезда** (решено, вопрос закрыт).
9. Скачивание треков из Deezer — нарушение ToS сервиса; используем с личным премиум-аккаунтом для личного пользования (как Saturn).

### Спайк 1 — скачивание Deezer (2026-07-31, другой ПК): ✅ УСПЕХ
- ARL валиден (user_id=4027451242, premium).
- **deezspot не работает**: его media API вызов падает (`JSONDecodeError`). Классический legacy-метод (`e-cdns-proxy-*.dzcdn.net/mobile/1/...`) **мёртв** — хосты удалены из DNS (NXDOMAIN даже через Cloudflare/Google DoH).
- **Рабочая цепочка** (свой код, `spike1_deezer_download.py`):
  1. GW `deezer.getUserData` (ARL cookie) → `checkForm` (api_token) + `USER.OPTIONS.license_token`;
  2. GW `song.getData` → `TRACK_TOKEN`, `DURATION`, `FILESIZE_FLAC/MP3_320`;
  3. `POST https://media.deezer.com/v1/get_url` {license_token, media.formats (нужный формат ПЕРВЫМ), track_tokens} → подписанный URL на `cdnt-stream.dzcdn.net`;
  4. скачивание + Blowfish CBC stripe (каждый 3-й 2048-байтный блок, ключ из md5(track_id) XOR "g4el58wc0zvf9na1").
- Проверено: FLAC 25.3 MB (226.4 c, 44.1 кГц/16 бит) и MP3_320 — оба проходят верификацию (mutagen + полное декодирование ffmpeg).
- Важно: media API возвращает только ПЕРВЫЙ формат из списка — для fallback запрашивать формат по одному.
- Список плейлистов: публичный `api.deezer.com/user/{id}/playlists` отдал 65 плейлистов (все public). Приватные этим способом не видны — в приложении использовать GraphQL `get_user_playlists`.
- ffmpeg на ПК нет — используем `imageio-ffmpeg` (бинарь в venv).
