Хороший прототип.
Ненадёжный синхронизатор.

DeckPipe уже решает реальную задачу: показывает Deezer и SoundCloud, ведёт локальную библиотеку, конвертирует аудио и читает Rekordbox. Но текущую версию нельзя считать безопасной для автоматической синхронизации рабочей DJ-библиотеки: семантика синка неполная, новые записи Rekordbox теряют метаданные, а локальный backend открыт любому сайту.

3/10
Статус: функциональный alpha-прототип, не production Положительные стороны — широкое покрытие сценариев, рабочая Unicode-цепочка API/UI, проверка длительности и бэкап перед записью. Блокеры — целостность Rekordbox, безопасность localhost API, XSS, отсутствие тестов и неуправляемый lifecycle backend.

Финальный контекст

Пользователь требовал не демонстрацию, а установленное приложение с полной функциональной и визуальной проверкой.

Задача Kimi зафиксировала source_deleted: true, но тот же журнал после операции всё ещё показывал исходный FLAC рядом с WAV. Проверялся флаг, а не постусловие на диске.

срочно В transcript присутствовали реальные credentials

В сессии были вставлены ARL Deezer, Telegram bot token/chat и SoundCloud token. Они намеренно не извлекались в отчёт. Их следует считать скомпрометированными и ротировать.

Архитектура и поток данных

Концепция разумна для персонального desktop-инструмента, но границы ответственности и транзакций размыты.

Deezer / SoundCloudнеофициальные API, cookies, yt-dlp, remote metadata
FastAPI backendглобальные jobs/cache, скачивание, конвертация, API без auth
Файлы + sidecarаудио и .deckpipe.json в пользовательских папках
Rekordbox master.dbпрямая запись через pyrekordbox, бэкап последних пяти
Tauri shellзапускает PyInstaller sidecar
WebView2открывает HTTP UI на loopback
Vanilla HTML/JSinnerHTML + inline handlers
Helper extensionпересылает cookies в найденный localhost port

Что сделано правильно

  • Backend слушает только loopback, а API конфигурации не возвращает raw-токены.
  • Перед записью в Rekordbox есть проверка, что приложение закрыто, и создаётся копия БД.
  • Файлы проверяются Mutagen + полным декодированием ffmpeg и сравнением длительности.
  • JSON и HTML используют UTF-8; ensure_ascii=False сохраняет читаемую кириллицу.
  • WAV-конвертация сверяет длительность и старается обновить ANLZ-пути.

Системная проблема

Операция «синхронизировать» распределена между remote API, очередью в памяти, аудиофайлом, sidecar и Rekordbox, но общего transaction/journal/reconciliation слоя нет. Поэтому частичный успех легко выглядит как полный.

Кириллица: фактическая картина

Под одним симптомом скрывались две разные категории. Их важно не смешивать.

Legacy replacement characters
23 Title / 22 Artist

Все 23 — существующие WAV с кириллицей в filename и реальным U+FFFD в базе.

DeckPipe blank metadata
68 Title / 72 Artist

Все 68 пустых Title точно сопоставлены с DeckPipe sidecar, где метаданные сохранены.

1. «Квадраты» / U+FFFD — подтверждены, но не приписываются DeckPipe

  • В 23 Title найдено 212 символов U+FFFD; в 22 Artist — ещё 228.
  • Все повреждённые Title относятся к WAV, все 23 filename содержат нормальную кириллицу.
  • Дата создания записей: 10 штук — 24.12.2024, 13 штук — 17.03.2025.
  • Они уже присутствуют во всех пяти DeckPipe-бэкапах 5 августа 2026 и не совпадают с текущими sidecar.
  • В самих WAV RIFF/INFO chunks присутствуют, но их значения ASCII; восстановить исходный Title из них нельзя.
Вывод с ограниченной причинностью. Сохранившиеся артефакты доказывают наличие старой порчи, но не доказывают, какой именно импортёр её создал. Наиболее правдоподобен старый WAV/Rekordbox metadata path, однако это inference, а не установленный виновник.

2. Пустые названия — подтверждённый дефект DeckPipe

  • 68 записей без Title: 66 FLAC и 2 MP3.
  • 4 созданы 4 августа 2026, 64 — 5 августа 2026.
  • Все 68 сопоставлены с десятью .deckpipe.json; файлы существуют, sidecar title не повреждены.
  • app/rekordbox.py:91 вызывает db.add_content(f) без Title, ArtistID, Album и других полей.
  • Реализация pyrekordbox database.py:1936-1952 создаёт только технические поля файла и переданные kwargs; она не читает теги автоматически.

Это не ошибка UTF-8. Это отсутствие записи метаданных, визуально похожее на «названия пропали».

Безопасный путь восстановления

  1. Сделать отдельную repair-команду только с --dry-run по умолчанию.
  2. Для 68 пустых записей построить mapping FolderPath → sidecar → Title/Artist и экспортировать preview CSV/HTML.
  3. Для 23 legacy U+FFFD брать данные только из проверенных тегов или подтверждённого пользователем файла; не угадывать Artist по имени.
  4. Перед apply: Rekordbox закрыт, уникальный timestamp+UUID backup, хеш, пробное открытие копии, затем единая транзакция.
  5. После apply: перечитать БД, проверить code points, количество строк и плейлисты; предоставить rollback.

Критичные технические находки

Приоритет учитывает вероятность, масштаб ущерба и наличие фактического воспроизведения.

Critical · SEC-01 Любой сайт может управлять локальным DeckPipe API

app/main.py:17-19 включает allow_origins=["*"], все методы и headers; authentication/CSRF token отсутствуют. Runtime-проверка с Origin https://attacker.invalid получила Access-Control-Allow-Origin: *; preflight к /api/rb/sync разрешил POST.

Потенциальный сценарий: открытая веб-страница вызывает localhost API, читает конфигурацию и запускает bind/download/RB sync/flip/report от имени пользователя. Loopback сам по себе не является контролем доступа.

Исправление: per-launch random bearer, привязанный к Tauri window; deny-by-default Origin/Host; отдельный nonce/confirmation для мутаций; убрать wildcard CORS.

High · RB-01 Новые треки попадают в Rekordbox без Title и Artist

Воспроизведено на реальной базе агрегатами: 68 пустых Title полностью совпадают с DeckPipe sidecar. Причина в app/rekordbox.py:88-95 и контракте pyrekordbox.add_content.

Исправление: создавать/переиспользовать Artist/Album и передавать нормализованные метаданные; отклонять commit, если обязательные поля пусты.

High · RB-02 «Sync playlist» не синхронизирует состояние

app/rekordbox.py:83-99 добавляет только отсутствующие ContentID. Старые треки не удаляются, существующие не переставляются, изменившиеся пути/метаданные не reconciliate. track_no=i применяется только к новым строкам.

Повторный запуск не приводит RB-плейлист к порядку streaming-плейлиста. UI и название операции обещают больше, чем выполняет код.

High · SEC-02 Stored XSS в названии плейлиста воспроизводится

app/static/index.html:351 и :661 вставляют remote title внутрь inline JavaScript string. Экранируются HTML-символы и одиночная кавычка, но не предшествующий backslash. Синтетический title \');…// вышел из строки; probe statement выполнился.

withGlobalTauri=true и csp=null в tauri.conf.json:11-14 повышают влияние: injected code имеет same-origin доступ к localhost API.

Исправление: строить DOM через textContent, хранить id/title в JS state, использовать addEventListener; включить строгий CSP без inline-script.

High · LIFE-01 Backend остаётся после закрытия EXE

После нормального CloseMainWindow() shell завершился, но оба deckpipe-backend.exe оставались живы более 12 секунд. Конфигурация не менялась, jobs были пусты.

Это сохраняет незащищённый API и credentials в памяти после визуального закрытия приложения и создаёт конфликт порта при следующем запуске.

Исправление: хранить sidecar child handle, завершать на RunEvent::Exit/ExitRequested, добавить parent-death watchdog и single-instance lock.

High · RB-03 WAV flip может сообщить успех без обновления Rekordbox

app/jobs.py:339-341 молча пропускает файл, которого нет в коллекции RB; затем sidecar получает flipped_to=wav. Ошибка commit кладётся в job.error, но state всё равно становится done (:367-373), а UI top-level error не показывает.

Заявление «все cues/grid/BPM сохранены» не подтверждается, если rb_updated < converted. Операция должна завершаться failed/partial и запрещать удаление source.

High · DATA-01 Нет единой блокировки и атомарности

Sidecar пишется напрямую (library.py:46-65) и на каждой записи перечитывается целиком. Несколько download/flip потоков выполняют read-modify-write без file lock. Flip запускает отдельный thread на каждый запрос; workers не ограничен.

Бэкап называется с точностью до секунды (rekordbox.py:33-40), поэтому параллельные операции могут перезаписать один backup. Нет lock на master.db и проверки восстановления копии.

High · SEC-03 Helper доверяет любому процессу на двух портах

extension/popup.js:1-8 считает DeckPipe найденным при любом HTTP 200 от /api/version. После этого читает ARL и SoundCloud OAuth cookie и POST-ит их на этот порт (:23-38).

Локальный процесс, первым занявший 24680/7100 и выставивший CORS, может выдать себя за DeckPipe. Нужен challenge-response с публичным ключом приложения или ручное pairing secret.

Остальные значимые дефекты
  • Неатомарная загрузка: аудио пишется прямо в конечный filename (deezer_client.py:117-132), без .part и atomic rename.
  • Коллизии: filename содержит только Artist + Title, но не provider/track ID; разные версии могут перезаписать друг друга.
  • Ложная верификация: существующий или fuzzy-adopted файл становится ok без полного verify_file (library.py:187-217).
  • Ошибки тегов скрываются: tagger.write_tags ловит exception и не меняет итоговый status.
  • Retry выбирает provider по target: local/dir цель с SoundCloud-треком повторяется как Deezer (main.py:823-829).
  • Errors неполны: endpoint собирает только Deezer и sc:, исключая local: и dir: (main.py:769-795).
  • Удалённые ошибки скрываются: search-download проглатывает exception добавления в Deezer и возвращает частичный успех (main.py:637-648).
  • Hardcoded Rekordbox path: %APPDATA%\Pioneer\rekordbox\master.db, приватный pyrekordbox.config.__config__; нет определения активного профиля/version.
  • Jobs исчезают при рестарте: очередь и результаты полностью in-memory (jobs.py:12-49).
  • Установленная версия устарела: OpenAPI EXE не содержит password login, хотя HEAD содержит; обе сборки называются 0.5.0.

Горячие точки

  • scan_playlist: fuzzy match каждого streaming track по списку файлов — O(tracks × files).
  • _set_track: каждый track повторно читает и полностью переписывает sidecar — итоговая стоимость близка к O(N²) по JSON-объёму.
  • Frontend строит коллекции через большой innerHTML; виртуализации нет. Уже есть плейлист на 3,649 треков.
  • Единственный serial download worker снижает throughput, а отдельные flip thread pools обходят эту очередь и могут перегрузить CPU/диск.

Ограничения и уровень уверенности

  • Высокая уверенность: CORS, XSS, blank RB metadata, append-only sync, orphan backend, min-size clipping, keyboard inaccessibility — воспроизведены или напрямую доказаны кодом + состоянием.
  • Средняя уверенность: точный первоисточник 23 legacy U+FFFD. Повреждение и возраст доказаны; виновник — нет.
  • Не проверялось: реальное скачивание, удалённое изменение Deezer/SoundCloud, запись/repair live master.db, качество cues/grid после настоящего flip.
  • Dependency security: npm audit выполнен; полноценные pip-audit/cargo-audit/SBOM невозможны без закреплённого Python dependency manifest и дополнительных инструментов.
Следующий безопасный шаг: не исправлять live DB напрямую. Сначала сделать isolated test fixture из копии, добавить RED-тесты на 68 blank records и playlist reconciliation, затем независимый review и только после этого — dry-run repair.
