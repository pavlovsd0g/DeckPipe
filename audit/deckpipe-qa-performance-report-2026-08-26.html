Проблема подтверждена в данных Rekordbox, а не только в UI

В базе: 1061 content row, 26 кириллических Title, 63 кириллических filename, 23 Title с replacement glyph и 68 пустых Title. 23/23 повреждённых Title относятся к WAV; их файлы существуют, а filename содержит кириллицу.

Интерпретация. Сильная корреляция с WAV и отсутствие non-ASCII в RIFF INFO у этих 23 файлов указывают на metadata/import path. Но причинность текущей DeckPipe 0.5.0 не доказана: повреждённые rows датированы 2024–2025, а текущий WAV flip меняет path/type/size, не Title/Artist. Нужен preview-only repair audit, не автоматическая перезапись.

06 / NEXT

Рекомендуемый порядок исправлений

QA-план реализован; дальше нужны отдельные change-итерации с RED/GREEN и обязательным backup/rollback для Rekordbox.

Закрыть P0 security gates из полного аудита

Per-launch auth для localhost, strict Origin/Host, убрать inline-handler XSS и blind helper pairing. Credentials remediation остаётся вне этого QA-run по прямому указанию владельца.

Спроектировать metadata-aware Rekordbox sync

Dry-run diff, add/remove/reorder/update, обязательные Title/Artist, post-commit reconciliation и idempotence. До этого RB write/flip считать experimental.

Сделать preview-only repair для существующей базы

Отдельно показать 23 U+FFFD и 68 empty Title, источники метаданных и confidence. Никакого автоугадывания или записи без ручного подтверждения и backup verification.

Исправить lifecycle sidecar

Хранить child handle, завершать backend на Exit/ExitRequested, добавить parent-death watchdog и single-instance/port lock.

Заменить fuzzy nested-loop индексом

Один раз нормализовать filename и ключи; сначала exact track-id/normalized key, затем ограниченный fuzzy fallback. Добавить perf gate на 200×1000.

Довести UI и error model

Responsive header, playlist card как semantic button/list item, Tab/Enter/Space, local_sources в errors, явные loading/partial/failure states.

Ограничения
