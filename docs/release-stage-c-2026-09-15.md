## Что изменилось для пользователя

Плейлист или «Лайки» собираются в Rekordbox по фактическим файлам всей общей библиотеки, включая вложенные и явно привязанные внешние папки. Приложение берёт полный порядок из выбранного источника. Локальные плейлисты доступны без входа в стриминг; состав сохраняется и тогда, когда все файлы уже найдены и скачивать ничего не нужно. Догрузка только недостающих треков сохраняет остальные записи локального плейлиста.

Перед записью показываются выбранный плейлист Rekordbox, добавления, удаления из него, перестановки и реальные пути файлов. Для одинаковых названий можно выбрать конкретный плейлист. Применяется только подтверждённый просмотр: изменения источника, файлов или базы требуют открыть его заново. Отмена и повторная синхронизация уже совпадающего плейлиста ничего не переписывают.

Сохраняются ContentID, ID оставшихся связей плейлиста, комментарии, ручные метаданные, cue-точки и сетка. Удаление из одного плейлиста не удаляет трек из коллекции и других плейлистов. Перед изменением создаётся проверенная резервная копия; журнал позволяет восстановить незавершённую операцию. Восстановление доступно отдельно, без выбранного плейлиста и соединения со стримингом. Пользователь подтверждает конкретную прерванную операцию; обычное подтверждение синхронизации не запускает восстановление. Затем требуется новый просмотр синхронизации.

Для WAV сначала создаются отдельные копии с сохранением исходников. Проверяется совпадение декодированного аудио, частоты, каналов и числа кадров; одной похожей длительности недостаточно. Затем пользователь отдельно подтверждает переключение путей в Rekordbox. Возврат к исходникам доступен после перезапуска. В просмотре отмечается влияние на другие плейлисты, использующие те же треки.

Если в Rekordbox пока есть только часть треков, интерфейс предлагает сначала синхронизировать состав и отдельно показывает фактический формат. Удалённый извне целевой плейлист требует нового выбора и просмотра. Проверка запущенного Rekordbox учитывает русскую Windows; неизвестный результат останавливает запись и возвращает понятную ошибку.

Браузерный сценарий использовал настоящие обработчики и собранный интерфейс с созданными SQLCipher/FLAC/ANLZ-данными. После каждого шага отдельный процесс перечитывал базу: порядок, ID, ручные поля, cue-точки, другой плейлист, хеши исходников и нетронутые секции анализа. После отмены и повтора отпечаток базы не менялся. Режим WAV после перезагрузки определялся по базе. Диалоги проверены визуально и клавиатурой; ошибок в консоли нет. Глобальное восстановление прошло после отключения тестовой папки музыки и перезагрузки страницы без выбранного источника.

Тесты восстановления включают завершение дочернего процесса на разных границах операции, WAL, параллельные записи, повреждённый журнал и резервную копию. Постороннее изменение не затирается восстановлением. Неподдерживаемая структура базы блокируется до первой записи.

Проверки источников и извлечённого EXE используют разные новые базы. В последнем случае работает штатный backend без подмены адаптера и проверки процессов. Числа в таблице относятся к отдельным наборам проверок и не складываются в количество уникальных тестов. Единственный пропуск Python — создание symlink, недоступное текущему Windows-аккаунту; архивное сравнение интерфейса на окончательном коммите прошло.

## Как пользоваться

1. Укажите общую папку музыки, дождитесь каталога и откройте источник или локальный плейлист. У всех его треков должны быть подтверждённые доступные файлы.
2. Закройте Rekordbox. Нажмите «→ RB», проверьте целевой плейлист, порядок и пути, затем примените показанный план. Для изменения состава сначала используется этот шаг.
3. Для WAV подтвердите подготовку отдельных файлов, затем проверьте и подтвердите смену путей. После перезапуска та же кнопка предложит возврат к исходникам.
4. После прерванной операции используйте «Rekordbox: восстановление» в верхней панели. Подтвердите конкретную операцию; после завершения откройте новый просмотр синхронизации.

## Что остаётся до выпуска

Этап D: проверить поддерживаемые версии Rekordbox на реальных коллекциях, установленное приложение, чистую установку/обновление/удаление, большую библиотеку и съёмные диски. Реальный вход в Deezer/SoundCloud, 2FA, переподключение и загрузки остаются отдельной приёмкой. Подпись и timestamp нужны для публичного релиза.

Финальная приёмка C выполнялась на сгенерированных базах и изолированных профилях Windows. Она подтверждает инженерное поведение, но не сертифицирует произвольную установленную версию Rekordbox. Пользовательская база не была объектом применения или копирования. Ранние диагностические пробы до полной изоляции не считаются доказательством отсутствия автоматического поиска конфигурации; после его обнаружения адаптер получил явную защиту, а окончательные проверки выполнены заново в изоляции.

Работа находится в отдельной ветке `codex/release-hardening`. Основной checkout, включая пользовательские изменения Orchestrator-тестов, сохранён. Слияние, публикация и установка не выполнялись.

HTML-версия отчёта проверена по структуре и ссылкам. Её визуальный просмотр через встроенный браузер заблокирован политикой локальных URL; это ограничение просмотра отчёта не относится к завершённой проверке интерфейса приложения на localhost.
