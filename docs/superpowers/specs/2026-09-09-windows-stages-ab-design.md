# DeckPipe: Windows, общая библиотека, этапы A и B

Статус: реализация одобрена пользователем 9 сентября 2026 после аудита. Последующее уточнение того же дня требует явного выбора общей папки до первой синхронизации.

## Границы

Единственная платформа текущего релиза — Windows. macOS исключён. SoundCloud сохраняет существующие yt-dlp/api-v2 механизмы загрузки, локального хранения, чтения плейлистов и лайков. Создание SoundCloud-плейлистов, официальный OAuth, полное совпадение возможностей с Deezer не являются обязательными. Этапы C/D и включение записи Rekordbox/flip остаются за пределами этой реализации.

## Этап A

Пользователь обязан выбрать общую существующую папку музыки. Отсутствующая настройка возвращает явное `music_root_required`; значение Music/DeckPipe не считается согласием. Прежний явно сохранённый корректный music_root принимается. Ошибка доступа и отключённый диск отличаются от пустой библиотеки.

Сканирование охватывает общую папку рекурсивно и явно привязанные папки. Индекс хранится в SQLite внутри каталога данных DeckPipe, не в музыкальной папке. Он содержит фактические пути, размер/mtime, доступность, метаданные и подтверждённые связи `(provider, track_id) -> file`. Sidecar в папках сохраняются для совместимости и переноса.

Плейлист — список ссылок на музыку, а не обязательная физическая папка всех его файлов. Его привязанная папка определяет назначение новых загрузок. Одинаковый трек из другого плейлиста/папки отображается как имеющийся, с полным путём и названием папки; новая копия не загружается. Общий каталог не перемещает и не переименовывает найденные файлы. При удалении/переносе файлы проверяются заново; недоступный корень не вызывает повторную массовую загрузку.

Сопоставление сначала использует подтверждённый provider ID из sidecar/каталога, затем точные artist+title с сохранением версии/mix и проверкой длительности, когда она известна. Разные версии и одинаковые названия разных исполнителей не объединяются. Несколько кандидатов дают `ambiguous` и выбор пользователю. Треки с неоднозначностью исключаются из автоматического "скачать недостающее" до выбора. Необработанные аудиофайлы без sidecar должны индексироваться по тегам/полному имени.

Активные дефекты аудита F01/F02/F08 исправляются: резервирование ownership, безопасные имена публикации, сохранение последней валидной backup-копии, восстановление rename после исключения/kill, исходный provider и stage в retry. Изменения записи Rekordbox не включаются.

## Этап B

Deezer должен выдавать всю коллекцию с контролем cursor/next, включая >50 плейлистов и длинные альбомы. Ошибки входа/доступа/сети/rate-limit и частичная выдача явно передаются в UI. Нельзя выдавать недоступный сервис за пустую коллекцию. SoundCloud download path остаётся yt-dlp; выдача страниц и частичные ошибки проверяются независимо от возможностей Deezer.

Локальная загрузка и добавление в Deezer имеют отдельные результаты. Неуспешное удалённое действие сохраняется, может быть повторено после restart; повтор сначала сверяет состав, чтобы не добавлять уже присутствующие ID после неопределённого результата запроса.

Вход: общий AuthBroker (`begin`, `complete`, `cancel`, `status`, `logout`, `refresh/relogin`). Он открывает системный браузер. Для существующих session-based клиентов нужен узко разрешённый browser adapter; один только callback URL не даёт доступа к сессии провайдера. Секреты не попадают в frontend, URL или логи; сохраняются через DPAPI после серверной проверки. Состояние одноразовое и ограничено по времени, провайдеру и источнику. Повтор callback и завершение отменённой/истёкшей операции запрещены. Logout очищает provider credentials и account-bound caches, сохраняя локальные файлы.

Текущий браузер по умолчанию — Firefox (подтверждён read-only ProgId). Для устойчивого браузерного помощника могут потребоваться подпись расширения и его установка самим пользователем. Код, тесты и пакет готовятся до запроса этого внешнего действия. Окончание технической реализации и реальный вход пользователя учитываются отдельно; live-вход не объявляется проверенным по синтетическому тесту.

## Приёмка

- Новые JSON/rename/media regression tests сначала воспроизводят старый дефект, затем проходят.
- Общая папка обязательна; явная привязка папки с другим именем сохраняется.
- Лайки находят два ранее сохранённых трека в разных вложенных папках; отсутствующий третий предлагается скачать. Повторный запуск сохраняет связи.
- Один трек в нескольких плейлистах не скачивается повторно, не перемещается и не перенумеровывается чужой синхронизацией.
- Другой артист, mix, одинаковый basename, NFC/NFD, перенос/удаление/недоступный корень, повреждённый sidecar и неоднозначность проверены.
- Pagination 0/1/50/51/120, повтор cursor, HTTP 401/403/429/5xx и partial response не скрываются.
- Retry SoundCloud в local/Deezer-цели остаётся SoundCloud; conversion retry использует готовый исходник.
- Auth: begin/cancel/expiry/replay/wrong provider/wrong browser source/logout/account switch, плюс native build и JS extension contracts.
- Полные существующие Python/PowerShell suites, frontend build, Rust check/test. Installed/live provider acceptance указывается отдельно.

## Принятые технические решения

SQLite выбран для общего индекса; sidecar и очередь не переписываются целиком. Общая папка и явно добавленные привязки — единственные области поиска. Символические ссылки/переходы за пределы этих областей автоматически не обходятся. Новые провайдеры, macOS и замена frontend framework не включаются.
