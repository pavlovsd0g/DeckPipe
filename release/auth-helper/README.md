# DeckPipe: вход через Firefox на Windows

**Историческая реализация, исключена из продуктового решения 14 сентября 2026.** Пользователь требует вход через любой системный браузер без расширений и регистрации Mozilla. Не выполнять эти инструкции для новой приёмки B: пакет сохранён для воспроизводимости прежних инженерных проверок. Актуальное требование — в `docs/release-plan-2026-09-09.md` исходного проекта.

Расширение открывает существующую сессию Deezer/SoundCloud только по вашему нажатию «Подключить к DeckPipe». Оно передаёт выбранную сессию напрямую нативному мосту; пароль, cookie и токен не копируются вручную и не показываются в интерфейсе. Локальное приложение проверяет сессию и хранит её через Windows DPAPI. Загрузчик SoundCloud остаётся прежним.

## Установка пользователем

1. Установите сборку DeckPipe, включающую `deckpipe-auth-host.exe` рядом с `deckpipe.exe`. Скрипт ниже не скачивает и не устанавливает программу.
2. В обычном PowerShell выполните `Register-DeckPipeAuthHost.ps1 -InstallDirectory 'абсолютный путь к папке DeckPipe'`. Это отдельное явное действие: оно создаёт единственный манифест в `%LOCALAPPDATA%\DeckPipe\AuthHelper\native-host.firefox.json` и одну запись `HKCU\Software\Mozilla\NativeMessagingHosts\com.deckpipe.auth`. Папка программы может быть в Program Files: запись рядом с EXE не требуется. Повторный запуск для той же установки безопасен; запись другой установки скрипт не перезаписывает. После обновления этой версии выполните регистрацию заново: проверенная старая запись рядом с EXE будет перенесена, а старый манифест останется нетронутым.
3. Установите подписанный Mozilla XPI в том профиле Firefox, который открывается как браузер по умолчанию. Стабильный ID: `deckpipe-auth@deckpipe.local`. В этой инженерной сборке XPI **не подписан**. Постоянная установка в обычный Firefox требует подписанного XPI; пакет не изменяет политики браузера и настройки проверки подписи.
4. Для временной QA-проверки пользователь может открыть `about:debugging`, «Этот Firefox», «Загрузить временное дополнение» и выбрать `extension/manifest.json` из этой папки. После перезапуска Firefox дополнение исчезнет. Этот способ не подтверждает постоянную установку и запросы разрешений подписанного пакета.
5. В DeckPipe нажмите «Войти через браузер». В Firefox войдите на сайт сервиса обычным способом, откройте расширение и нажмите «Подключить к DeckPipe». При первом подключении разрешите доступ только к выбранному сервису. Для контейнера используйте активную вкладку именно этого контейнера. Приватные окна не поддерживаются.
6. После подтверждения приложение вернётся на передний план, если Windows разрешит перевод фокуса. Иначе вернитесь в DeckPipe вручную. Перед синхронизацией отдельно выберите общую папку музыки.

`helper.state=not_connected` означает отсутствие связи с расширением, а не доказанное отсутствие установки. Проверьте профиль, установленное дополнение и регистрацию моста. При перезапуске/отмене начните новую попытку; окно ожидания ограничено пятью минутами.

Выход в DeckPipe удаляет только выбранную локальную авторизацию и сбрасывает кэши. Он не выходит из аккаунта в Firefox и не удаляет аудиофайлы. Удаление регистрации: `Unregister-DeckPipeAuthHost.ps1 -InstallDirectory 'абсолютный прежний путь к папке DeckPipe'`. Путь можно передать и после удаления папки программы; скрипт удаляет только совпадающую запись и принадлежащий ей per-user манифест.

## Сборка и границы проверки

`Build-AuthHelper.ps1` из исходного проекта собирает нативный EXE в Cargo target. Tauri включает его в установщик как отдельный Cargo-бинарник рядом с `deckpipe.exe`; добавлять helper повторно в `externalBin` нельзя. В `externalBin` остаётся только Python backend. `package_helper.py` создаёт детерминированные ZIP/XPI в указанной лабораторной папке; эти файлы не подписаны. Подписание unlisted XPI требует аккаунта AMO, отправки Mozilla и прохождения её проверок. Отправка, установка, регистрация в HKCU и вход пользователя не выполняются сборкой.

Автоматические тесты используют вымышленные значения и изолированные named pipes. Они не доказывают действительность реальных cookies, успешный вход провайдера или постоянную установку. Chrome/Edge пока не включены: их стабильные ID и отдельные пакеты не подготовлены; приложение не подменяет Firefox другим браузером.
